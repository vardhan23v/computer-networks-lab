# Experiment 2: TCP and UDP Traffic: Packet Counts and Throughput

## 🎯 Aim & Objective
Simulate a four-node point-to-point network with links connected as: `n0-n2`, `n1-n2`, and `n2-n3`. Attach a TCP agent between `n0` and `n3`, and a UDP agent between `n1` and `n3`. Generate FTP traffic over TCP and CBR traffic over UDP, analyze packet counts, and calculate network throughput over time using AWK and Xgraph.

---

## 📦 Required Tools & Simulation Parameters

| Component | Specification |
|---|---|
| **Simulator** | NS-2 (`ns` v2.35) |
| **Trace Analysis** | AWK (`exp2.awk` for packet counts, `exp2_throughput.awk` for throughput) |
| **Graphing Tool** | Xgraph (`xgraph plot_throughput`) |
| **Topology** | 4 Nodes (`n0` TCP sender, `n1` UDP sender, `n2` intermediate switch, `n3` sink) |
| **Links** | 1 Mbps bandwidth, 10ms propagation delay, DropTail queue (capacity 50) |
| **TCP Agent / Application** | `Agent/TCP` (node 0) to `Agent/TCPSink` (node 3) with `Application/FTP` (size: 1000 bytes) |
| **UDP Agent / Application** | `Agent/UDP` (node 1) to `Agent/Null` (node 3) with `Application/Traffic/CBR` (size: 500 bytes, interval: 0.005s) |
| **Traffic Timings** | CBR starts at `0.5s` and stops at `4.5s`; FTP starts at `0.75s` and stops at `4.75s` |

---

## 📂 Files in this Experiment

- [`exp2.tcl`](./exp2.tcl) - Simulation script creating the 4-node topology, TCP/FTP and UDP/CBR flows.
- [`exp2.awk`](./exp2.awk) - AWK script counting total packets transmitted by TCP and UDP.
- [`exp2_throughput.awk`](./exp2_throughput.awk) - AWK script computing instantaneous throughput in Kbps.

---

## 🛠 Execution Instructions

```bash
# 1. Run NS-2 simulation
ns exp2.tcl

# 2. Count packets generated by TCP and UDP
awk -f exp2.awk out.tr

# 3. Generate throughput data points and redirect to file
awk -f exp2_throughput.awk out.tr > plot_throughput

# 4. Plot throughput graph using Xgraph
xgraph plot_throughput

# 5. Inspect generated throughput values
head -3 plot_throughput; tail -2 plot_throughput
```

## 🔍 Code Walkthrough

### 1. Network Setup (`exp2.tcl`)
- **Shared Bottleneck:** Nodes `n0` (TCP) and `n1` (UDP) both transmit to destination node `n3` through the shared link `n2-n3` (1 Mbps capacity).
- **TCP Characteristics:**
  - Employs congestion control (slow start, congestion avoidance).
  - Uses `Agent/TCPSink` for ACK generation.
  - FTP traffic starts at $t = 0.75\text{s}$ and terminates at $t = 4.75\text{s}$.
- **UDP Characteristics:**
  - Unresponsive to congestion (inelastic CBR stream).
  - CBR generates 500-byte packets every 0.005s (800 Kbps).
  - Begins at $t = 0.5\text{s}$ and ends at $t = 4.5\text{s}$.

### 2. AWK Packet Count Logic (`exp2.awk`)
- Inspects field `$5` of each trace event:
  - If `$5 == "cbr"`, increments `udp_count`.
  - If `$5 == "tcp"`, increments `tcp_count`.

### 3. Throughput Calculation Logic (`exp2_throughput.awk`)
- Records transmission start time when enqueue event occurs (`$1 == "+"`):
  - `if (time < startTime) startTime = time;`
- Records receive events at destination (`$1 == "r"`):
  - Accumulates received payload size: `sSize += size;`
  - Updates end timestamp: `if (time > stopTime) stopTime = time;`
  - Calculates throughput in Kilobits per second (Kbps):
    $$\text{Throughput (Kbps)} = \left(\frac{\text{sSize}}{\text{stopTime} - \text{startTime}}\right) \times \left(\frac{8}{1000}\right)$$

## 💡 Viva Questions & Key Takeaways

1. **Why does UDP generate significantly more packets than TCP (4786 vs 846)?**
   - UDP with CBR operates in an open loop without flow control or congestion backoff—it blindly pumps packets onto the wire every 0.005 seconds. TCP is a closed-loop protocol constrained by the 3-way handshake, congestion window ramps (AIMD), and round-trip ACK delays.
2. **What happens when TCP and UDP share a bottleneck link?**
   - Inelastic UDP traffic can starve responsive TCP traffic. When the intermediate queue fills up, packet drops cause TCP to halve its congestion window and throttle back, whereas UDP continues transmitting at full speed without backing off.
3. **What is the difference between `Agent/TCP` and `Agent/TCPSink`?**
   - `Agent/TCP` is the sender-side transport agent that handles window sizing, sequence numbers, timeouts, and retransmissions.
   - `Agent/TCPSink` is the receiver-side agent that reconstructs byte streams and returns cumulative ACKs to the sender.
4. **How is throughput derived from NS-2 trace files?**
   - Throughput is the total volume of successfully received data bits divided by the total active transmission time interval, scaled by $\frac{8}{1000}$ to express in Kbps.
